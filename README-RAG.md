# 本地知识库助手

入口 `src/knowledge_assistant.py` 从原来的 `ds7.py` 重命名并扩展；`ds6.py` 不参与本次修改。

## 启动

在 PowerShell 中运行：

```powershell
Set-Location D:\miniAgent
& .\.venv\Scripts\python.exe .\src\knowledge_assistant.py
```

浏览器访问 `http://127.0.0.1:7860`。先确保 Ollama 已启动，且 `ollama list` 包含 `bge-m3:latest`。
大模型、embedding、重排、端口和日志级别统一从项目 `.env` 读取，示例见 `.env.example`。
VS Code 的项目默认解释器也已指向 `.venv`；若之前手动选择过解释器，
请在状态栏重新选择 `D:\miniAgent\.venv\Scripts\python.exe`。

本地 `.venv` 位于项目目录，通过 `--system-site-packages` 复用已有的
`C:\Users\PC\.conda\envs\agent-dev` 依赖；新增的 pypdf、rank-bm25、jieba 安装在 D 盘。
该环境依赖原有 agent-dev 环境，并非可独立搬走的环境。
`requirements-rag.txt` 提供独立重建环境时的依赖清单。

## 使用

1. 在“知识库管理”中选择 TXT、Markdown 或文字版 PDF，点击“导入 / 更新资料”。
2. 等待看到导入成功，再提问。默认启用“优先检索知识库”；闲聊可关闭。
3. 回答正文使用 `[资料1]` 等编号。回答下方列出本次检索到的候选资料，展开可核对原文。
   候选列表不表示每个片段都支持回答中的所有结论，以正文引用和实际原文为准。
4. “清空聊天记录”仅清空此入口的聊天记录，保留原始资料和向量库。
5. 删除资料时，在文档列表下选择文件，核对待删除清单并勾选确认，点击“删除所选文档”。

原文块、向量及来源位置一起保存在 ChromaDB。文档与问题都由 Ollama 的同一个 BGE-M3 模型编码。
默认使用 BM25 + BGE-M3 混合检索：两路各召回 20 块，按块 ID 去重后进行等权 RRF 排名融合，
融合后默认取前 20 个候选进行本地重排，过滤低于阈值的片段，最多选择 4 块交给大模型；
参考原文总长上限为 12000 字符。默认开启“仅依据知识库回答”，无片段通过筛选时程序直接说明资料不足。
相关性评分不等于证据完整性，模型仍需在依据不足时说明，引用需要核对。
当前开关启用时每次提问都检索，不依赖模型自主决定是否调用检索工具。

## 混合检索与前端参数

“检索设置与候选分数”中可以选择混合检索、仅向量检索或仅 BM25，方便对比。
最终片段上限可调为 1–10，每路候选可调为 10–60。候选数量不等于发送给模型的数量。
BM25 不调用 Ollama；混合与向量模式需要 Ollama，连接失败会显示错误，不会悄悄切换检索模式。

BM25 使用中文分词并保留错误码、型号、函数名；英文转小写。
实现使用 `rank-bm25` 的 BM25Plus（delta=0），未匹配关键词的块不进入 BM25 候选。
分词词典缓存位于 `.cache/jieba-rag.cache`。BM25 索引只保存在进程内存中，首次检索时从
Chroma 文本构建，后续复用；导入或重新分块时失效重建。重启后可直接从现有文本重建，
不需要为添加 BM25 重新生成已有文档向量。当前面向单进程使用，其他进程写入不会自动刷新内存索引。

前端表格显示本次两路候选融合后的排名、是否送入回答、文档位置、向量相似度、BM25 分数、
RRF 分数及各自排名，以及重排分数、评分窗口数和筛选结果；开启重排后按重排分数展示已重排的候选。
空值表示该块未入选对应检索通道或未参与评分，并不代表分数为零。
RRF 使用 `1/(60+名次)` 累加，不能把它与 BM25 或向量相似度直接比较，也不能将其理解为正确率。
回答下方的原文展开区域也包含该片段的分数。只有送入本轮回答的片段会分配 `[资料N]`。

“知识库管理”中可设置每块字符上限（200–4000）与重叠大小，默认仍为 1200 / 180。
重叠必须小于块大小的一半。修改参数后重新选择原文件导入，会重新生成该文件的块与向量，
成功后清理旧块。内容哈希和分块配置共同决定是否跳过；旧版索引缺少配置指纹时，
下次手动导入会重建该文档，不会自动批量改写已有资料。

## 本地重排、阈值与资料不足

默认模型是 `BAAI/bge-reranker-base` 的 ONNX INT8 转换版，来自
[Xenova/bge-reranker-base](https://huggingface.co/Xenova/bge-reranker-base)。
固定 revision 为 `280bcc27a84e0b898c251e06fddb25171bd9b101`，下载脚本对模型和 tokenizer 校验 SHA256。
模型与 tokenizer 共约 296 MB，保存在 `D:\miniAgent\models\bge-reranker-base`。
当前机器已有 ONNX Runtime 和 tokenizers，直接复用；没有安装 PyTorch、CUDA 或迁移 Ollama 模型。
采用 CPU 推理，避免与已占用较多显存的 Ollama 竞争。模型只加载一次，默认每批 4 个窗口、6 个计算线程。

重建环境后先下载模型：

```powershell
& .\.venv\Scripts\python.exe .\src\setup_reranker.py
```

聊天时不会自动联网下载模型，缺失或运行失败会明确报错；可以手动关闭重排，回到第一阶段检索。
每个问题和候选片段由 Cross-Encoder 联合评分，而不是再次比较 embedding。
模型单窗口最多 512 token，长片段使用重叠窗口全部评分并取最大值，避免只看开头。
问题超过 128 token 时，仅重排使用前 128 token，并在过程信息中提示；生成服务仍接收完整问题。
长片段会增加窗口数与 CPU 耗时，可减少候选数量或调整分块大小。

“重排最低分数”默认 **0.20**，来自本地合成集校准；“最多重排候选数”默认 20，可调 10–40。
最终片段数、重排上限和每路召回数分别控制三个阶段。超出重排上限的候选只用于诊断，不会绕过阈值进入回答。
关闭重排时，该阈值不生效，不额外套用一个未经校准的向量相似度阈值。
Sigmoid 把模型原始分数映射为 0–1，但它不是答案正确概率。阈值越高通常越容易拒答，也越可能漏掉有效资料。

仅知识库模式下：

- 无候选通过：不调用生成模型或历史压缩，直接说明资料不足。
- 部分问题有依据：只回答有资料支持的部分，明确说明缺失字段；禁用联网和文件工具，历史对话不作为事实依据。
- 正文出现不存在的 `[资料N]` 编号：程序标为无效引用；原文是否支持结论仍需要核对。

关闭“仅依据知识库回答”后会恢复原有工具能力和常识回答方式；关闭知识库检索时该限制也不生效。
重排和阈值都无法证明资料包含答案。测试中，无答案的“保修年限”候选分数约 0.396，
高于一个有答案的启动排查候选（约 0.365），因此不存在一个能完美区分这两个样例的单一阈值。
默认 0.20 优先保留有效证据，不能保证所有无答案问题都在程序层拒绝，仍需要模型检查缺失事实。

## 文件位置与更新规则

- `knowledge/`：导入的原始文档，按文件名识别同一文档。
- `knowledge/.versions/<内容哈希>/`：同名更新时保留旧原文；不同资料请使用不同文件名。
- `data/chroma/`：持久化向量库；不要在程序运行时手工修改里面的文件。
- `.cache/gradio/`：网页上传缓存。
- `sessions/knowledge_history.json`：新助手专用聊天记录，不覆盖旧版 `history.json`。
- `.venv/`：D 盘虚拟环境。
- `models/bge-reranker-base/`：重排模型、tokenizer 与下载版本记录。
- `data/trash/<UTC 时间与唯一批次号>/`：删除的原文和索引恢复快照。

相同内容和分块设置重复导入会跳过；同名文件内容或分块设置变化后重新生成向量，成功后清理旧块。
手工删除原始文件不会自动删除向量记录；请使用界面删除功能清理残留索引。
单文件限制 30 MiB。PDF 标注的是文件页序号，不一定等于书页印刷页码。
Markdown 记录标题与行范围，TXT 记录行范围，另附块在该章节内的字符范围。
扫描 PDF 需先做 OCR。仅导入显式选择的文档，不扫描项目目录或 `.env`。

Ollama 已有模型继续由 Ollama 管理，不重复下载，也不自动迁移到 `models/`。
所有新增项目数据目录均已加入 `.gitignore`。

## 删除文档与恢复

“知识库管理”会列出文件名、文本块数和原文件是否存在。页面打开、导入完成和删除完成时刷新，
也可以手动点击“刷新文档列表与状态”。没有向量记录的原文件及没有原文件的残留索引也可删除。
选中文档后会显示待删除清单；更改选择时之前的确认自动取消，必须重新核对。

删除按文件名逐个执行：先保存包含 ID、原文块、元数据和向量的恢复快照，再把原文件移到
`data/trash/<批次>/`，最后删除 Chroma 中该文档的记录并清除内存 BM25 缓存。
导入、删除和整轮网页聊天共用一个操作队列，删除不会插入正在生成的回答中途；
删除后刷新列表并清空候选分数表，其他文档不需要重新生成向量。

删除是“退出当前知识库检索”，不是彻底擦除全部副本：原文件在回收站保留，`.versions` 中的
旧版本和已有聊天记录都保留。历史回答中的引用、已发送给模型服务的内容不会被追溯撤回。
界面不提供大模型删除工具，也不支持任意路径删除。

文件移动失败时数据库保持原样；数据库删除中途失败时尝试从快照恢复索引并将原文件移回。
失败结果会说明是否恢复成功，并给出恢复材料所在目录；批量删除可能部分成功，请逐项查看结果。
文件系统与 Chroma 没有跨系统事务，突然断电或强制结束进程不能保证自动回滚。
遇到这类中断，可检查回收批次的 `manifest.json`：`prepared` 表示尚未完成，`deleted` 表示成功，
`rolled_back` 表示已回滚，`rollback_failed` 表示需根据结果检查原文与索引。

正常恢复误删文档时，在上传入口选择回收站中的原文，重新导入即可重新生成索引。
当前没有“一键恢复”或“清空回收站”功能，不会自动清理回收材料或旧版本。

## 可选配置

在 `.env` 中按需增加（不修改也可运行）：

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
RAG_EMBED_MODEL=bge-m3:latest
# 仅支持相同 ONNX 文件布局与模型结构的本地目录，不可直接换成其他架构：
RAG_RERANK_MODEL_DIR=D:/miniAgent/models/bge-reranker-base
```

不要把已有 collection 切换到其他 embedding 模型；新模型需要独立库并重新索引。
本版面向单进程本机应用，不支持多个进程同时导入同一库。
文档解析、向量生成及检索都在本机完成，但命中的文本块会发送到当前配置的大模型服务。

## 命令行导入与检查

```powershell
& .\.venv\Scripts\python.exe .\src\ingest.py .\knowledge\你的资料.md
& .\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
& .\.venv\Scripts\python.exe -B .\tests\evaluate_retrieval.py
& .\.venv\Scripts\python.exe -B .\tests\evaluate_rerank.py
& .\.venv\Scripts\python.exe -B .\tests\smoke_document_management.py
```

测试使用真实的本机 Ollama embedding 和独立临时向量库，需运行 Ollama。
测试文件与临时向量库位于 D 盘 `.cache/` 下，与正式库隔离。
删除测试覆盖正常删除、两路检索清除、原文缺失、未索引文件、移动失败、数据库部分删除回滚、
回滚失败报告、非法路径拒绝以及前端确认；网页删除验证不调用大模型。

`tests/fixtures/retrieval_cases.json` 包含 6 份合成文档和 10 个标注问题，覆盖错误码、函数名、
语义表达、多文档、有答案、无答案和部分有答案情况；不包含用户原有资料。
评估脚本分别运行向量、BM25 和混合检索，输出期望来源召回率、首个相关片段的倒数排名均值，
以及无答案问题仍返回候选的数量。完整候选分数和人工标注的已知/缺失事实写入
`.cache/retrieval-evaluation-*/report.json`。这些是来源检索指标，不能当成回答正确率；
这个脚本保留第一阶段的无重排基线，无答案问题仍会返回候选，用于对比。
可用 `--top-k 2 --candidate-k 20` 对比参数，后续应补充真实资料中的问答样例再校准阈值。

`evaluate_rerank.py` 用前述 10 个问题校准阈值，再用 `rerank_validation.json` 中 8 个保留问题验证。
阈值在 0.05–0.95 上按证据代理标签 F1 选择；代理标签要求来源正确且块中包含人工标出的已知事实。
当前工作点 0.20：校准集证据精确率 0.90、召回率 1.00，2 个无答案问题拒绝了 1 个；
验证集保留了全部 6 个有依据问题的证据，并拒绝全部 2 个无答案问题。
验证问题与校准问题共享合成文档，样本很小；这些指标不等于真实文档效果或大模型答案正确率。
真实资料还需补充标注问答重新校准。报告保存在 `.cache/rerank-evaluation-*/report.json`，不会自动改写默认阈值。

可选完整网页验证（会调用当前配置的大模型服务，验证有依据、无依据及部分有依据回答）：

```powershell
& .\.venv\Scripts\python.exe -B .\tests\smoke_assistant.py
```
